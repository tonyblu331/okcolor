## The useful middle between translation and saturation

Converting `#ff5a00` to `oklch(...)` is only a translation. Blindly making it louder is a brand risk. okcolor sits in the middle: preserve lightness and hue, find the chroma ceiling for Display P3, choose a controlled amount, then prove the fallback and enhancement are valid.

## Ship tokens, not vibes

```bash
okcolor expand tokens.json --gamut p3 --amount 0.75 --audit
```

Modern CSS functions pass through untouched: `oklch()`, `oklab()`, `lab()`, `lch()`, `color-mix()`, `light-dark()`, relative colors like `rgb(from red r g b)`, `var()`, and `calc()`.

## Scanner behavior

Converted:

- Raw declaration snippets like `color: red;`
- Rules and nested rules
- CSS custom properties, including escaped names like `--\31 brand`
- Color-capable shorthands such as `background`, `border`, `box-shadow`, `text-shadow`, `text-emphasis`, SVG `fill`/`stroke`, and related `*-color` properties
- `@supports (color: red)` declaration conditions
- `@container style(color: blue)` queries
- `@property --brand { syntax: "<color>"; initial-value: red; }`
- Gradients, including multiline gradients and `//` comments

Preserved:

- Selectors and selector functions like `:is(a:hover #abc, .red)`
- `@supports selector(...)` arguments
- Identifier-only properties such as `animation-name`, `font-family`, `grid-area`, `container`, `scroll-timeline`, `counter-reset`, and `view-transition-name`
- URLs, strings, comments, modern colors, and ignored lines

<div class="callout-card">
  <strong>Escape hatch:</strong> Add <code>/* oklch-ignore */</code> on any line to preserve the original color unchanged. Custom ignore comments are shielded with a sentinel, so unrelated <code>oklch-ignore</code> text in strings or content is not rewritten.
</div>
