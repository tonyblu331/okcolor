## Why OKLCH?

<CardGrid stagger>
  <Card title="Perceptually Uniform" icon="open-book">
    Equal steps in OKLCH lightness look equally different to the human eye. `oklch(0.5 0.2 180)` is visually halfway between black and white — unlike HSL where `lightness: 50%` varies wildly by hue.
  </Card>
  <Card title="Wide Gamut Ready" icon="seti:json">
    OKLCH covers every color the human eye can see. As displays move from sRGB to Display P3 and Rec. 2020, your design system is already there.
  </Card>
  <Card title="Verified Math" icon="open-book">
    Every conversion uses the exact W3C CSS Color Module Level 4 matrices. Verified against Culori — the reference implementation — with sub-5e-5 error across the entire sRGB gamut.
  </Card>
  <Card title="Zero Runtime Overhead" icon="rocket">
    All processing happens at build time in Rust via WASM. Your users download the result, never the engine. **~55 MB/s** throughput. Sub-millisecond for typical stylesheets.
  </Card>
</CardGrid>

Modern CSS functions pass through untouched: `oklch()`, `oklab()`, `lab()`, `lch()`, `color-mix()`, `light-dark()`, `var()`, `calc()`.

## Real-world demo

<div class="playground-grid">
  <div class="playground-pane playground-pane-input">
    <span class="playground-pane-label">Input</span>
    <pre>{`.hero {
  color: #ff0000;
  background: linear-gradient(#00ff00, #0000ff);
}
.btn {
  border: 2px solid hsl(145, 63%, 49%);
  box-shadow: 0 2px 4px rgb(0 0 0 / 20%);
}
.badge {
  background: rebeccapurple;
  color: white;
}`}</pre>
  </div>
  <div class="playground-pane playground-pane-output">
    <span class="playground-pane-label">Output</span>
    <pre>{`.hero {
  color: oklch(62.8% 0.25768 29.23);
  background: linear-gradient(in oklch, oklch(86.64% 0.29483 142.5), oklch(45.2% 0.31321 264.05));
}
.btn {
  border: 2px solid oklch(67.72% 0.19 152.54);
  box-shadow: 0 2px 4px oklch(0% 0 0 / 0.2);
}
.badge {
  background: oklch(38.31% 0.14883 299.97);
  color: oklch(100% 0 0);
}`}</pre>
  </div>
</div>

Running the conversion a second time produces the exact same output. **The engine is idempotent.**
