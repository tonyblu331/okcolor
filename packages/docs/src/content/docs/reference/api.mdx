## Package exports

okcolor exposes three entry points:

| Entry             | What you get                                      | Use when                                |
| ----------------- | ------------------------------------------------- | --------------------------------------- |
| `okcolor`         | Vite plugin factory                               | You're adding okcolor to a Vite project |
| `okcolor/core`    | Node/programmatic transform, audit, token compiler | You are writing build scripts or adapters |
| `okcolor/browser` | Browser WASM adapter                              | You intentionally ship a color tool UI  |

```ts
// Vite plugin
import { okColor, type OkColorOptions } from 'okcolor'

// Advanced build tooling
import { transformCss, auditCss, compileTokens, expandChroma, describeColor, type ScanResult } from 'okcolor/core'

// Advanced runtime color tools only
import { initOkColorBrowser, colorToOklch } from 'okcolor/browser'
```

---

## Browser adapter

`okcolor/browser` is the optional runtime seam for playgrounds, inspectors, color pickers, and design-system tools. It is not the default frontend app path. Normal apps should use the Vite plugin so okcolor runs during build and ships no runtime code.

```ts
import { colorToOklch, initOkColorBrowser, transformCss } from 'okcolor/browser'

await initOkColorBrowser()

console.log(colorToOklch('#ff5a00'))
console.log(transformCss('.btn { color: #ff5a00; }'))
```

The adapter exposes `OKCOLOR_WASM_URL` for preloading/custom asset handling and throws a clear error if a WASM API is called before `initOkColorBrowser()`.

The browser adapter is a separate package export. The root Vite/plugin entry and `okcolor/core` do not import it, so normal build-time usage stays tree-shakeable.

## `transformCss(input)`

Transforms a CSS string, converting all legacy colors to OKLCH. The Rust/WASM engine processes the entire string in a single pass.

```ts
function transformCss(input: string): string
```

  </tbody>

### Returns

`string` — the transformed CSS. All recognized legacy colors are replaced with `oklch()`.

### Examples

```ts
import { transformCss } from 'okcolor/core'

// Hex to OKLCH
transformCss('.btn { color: #ff0000; }')
// => '.btn { color: oklch(62.8% 0.25768 29.23); }'

// Multiple formats in one pass
transformCss(`
  .card {
    color: #f00;
    background: linear-gradient(#00f, #0f0);
  }
`)
// => all colors converted, gradient gets 'in oklch' hint

// Idempotent: second pass is a no-op
const first = transformCss('.btn { color: #ff0000; }')
const second = transformCss(first)
console.log(first === second) // true
```

Gradient color stops get `in oklch` injected for perceptually uniform interpolation. Modern CSS functions (`oklch()`, `oklab()`, `lab()`, `lch()`, `color-mix()`, `light-dark()`, relative colors, `var()`, `calc()`, etc.) pass through untouched.

### Scanner rules

The scanner is value-aware rather than a blind string replacement. It converts legacy colors in declarations, gradients, CSS custom properties, color-capable shorthands, `@supports` declaration conditions, `@container style(...)` queries, `@page` margin boxes, and `@property` registrations whose `syntax` descriptor includes `<color>`.

It preserves selector syntax, `@supports selector(...)` arguments, strings, URLs, comments, ignored lines, modern color functions, and identifier-only properties such as `animation-name`, `font-family`, `grid-area`, `container`, `scroll-timeline`, `counter-reset`, and `view-transition-name`.

## `auditCss(input)`

Scans a CSS string and reports legacy color statistics without transforming.

```ts
function auditCss(input: string): ScanResult
```

      </td>
      <td>
        <code>string</code>
      </td>
      <td>Raw CSS source to audit</td>
    </tr>
  </tbody>
</table>

### Returns

```ts
interface ScanResult {
  css: string // Original CSS (unchanged)
  legacy_count: number // Total legacy colors found
  hex_count: number // #RGB, #RRGGBB, #RGBA, #RRGGBBAA
  rgb_count: number // rgb(), rgba()
  hsl_count: number // hsl(), hsla()
  hwb_count: number // hwb()
  named_count: number // red, blue, etc.
  gradient_count: number // linear/radial/conic-gradient
  unique_count: number // Unique colors (by cache key)
}
```

### Example

```ts
import { auditCss } from 'okcolor/core'

const stats = auditCss(`
  .btn { color: #3b82f6; }
  .card { border: 1px solid hsl(145, 63%, 49%); }
  .hero { background: linear-gradient(red, blue); }
`)

console.log(stats.legacy_count) // 4
console.log(stats.hex_count) // 1
console.log(stats.hsl_count) // 1
console.log(stats.named_count) // 2
console.log(stats.gradient_count) // 1
```

## Token compiler API

The token compiler works on color token JSON and emits fallback-first CSS, a structured report, and Design Tokens-compatible JSON.

```ts
import { compileTokens, describeColor, expandChroma } from 'okcolor/core'

const result = await compileTokens('src/tokens/colors.json', {
  targets: {
    base: { gamut: 'srgb', strategy: 'convert', format: 'hex' },
    p3: { gamut: 'p3', strategy: 'expand', amount: 0.75, format: 'oklch' },
  },
})

console.log(result.css)
console.log(result.report.schemaVersion)
console.log(result.report.tokens)
console.log(result.report.diagnostics)
```

Supported token shapes:

```json
{
  "brand.orange": "#ff5a00",
  "color.action.primary.bg": {
    "$type": "color",
    "$value": "#0055ff",
    "okcolor": {
      "recipe": "premium",
      "text": "color.action.primary.fg",
      "contrast": "wcag2-aa"
    }
  },
  "color.action.primary.fg": "#ffffff"
}
```

Malformed or unsupported token shapes do not disappear silently. They are skipped and reported in `result.report.diagnostics`:

The report contract is versioned at the top level. `result.report.schemaVersion` is `1` for the current token compiler report shape; bumping it means frontend CI integrations should re-check their parser expectations.

```ts
type TokenParseDiagnosticKind = 'unsupported-token-shape' | 'unsupported-color-space' | 'invalid-color-components'

interface TokenParseDiagnostic {
  token: string
  kind: TokenParseDiagnosticKind
  severity: 'warning'
  path: string
  message: string
}
```

Only sRGB Design Token component objects are accepted today. A token using another `$value.colorSpace` is reported as `unsupported-color-space`; invalid component arrays are reported as `invalid-color-components`.

Unknown recipes are hard failures. Built-in recipes are `literal`, `vivid`, `deeper`, `premium`, `muted`, `softer`, `warmer`, and `cooler`; custom aliases must be declared in `options.recipes`.

### Color transforms

```ts
const color = expandChroma('#ff5a00', { gamut: 'p3', amount: 0.75 })
const description = describeColor('#ff5a00', { gamut: 'p3' })
```

`expandChroma()` preserves OKLCH lightness and hue, then increases chroma toward the target gamut boundary. Low-chroma neutrals are protected by a `0.02` chroma threshold so gray tokens do not get invented hues.

### Contrast report shape

Contrast is a foreground/background pair property. A background token declares its foreground via `okcolor.text`; the background token owns the report entries:

```ts
result.report.tokens[0].contrast.wcag2['color.action.primary.fg@srgb']
// {
//   foreground: 'color.action.primary.fg',
//   background: 'color.action.primary.bg',
//   target: 'srgb',
//   ratio: 6.82,
//   required: 4.5,
//   requirement: 'wcag2-aa',
//   status: 'pass'
// }

result.report.summary
// { contrastPassed: true, failureCount: 0, failures: [] }
```

WCAG 2 AA is the default blocking model. Override it at build time with `audit.wcag2.level: 'aaa'` or `audit.wcag2.requiredRatio`. APCA is advisory: report entries include `lc`, `polarity`, and an advisory `pass-body`/`pass-large`/`fail` hint. The implementation is checked against the W3-licensed `apca-w3` package as a test oracle, but APCA still does not replace WCAG 2 AA for CI gating.

Pair-level status is also reported, including skipped pairs where one side could not be compiled:

```ts
result.report.contrastPairs
// [
//   {
//     background: 'color.action.primary.bg',
//     foreground: 'color.action.primary.fg',
//     target: 'srgb',
//     status: 'evaluated',
//     wcag2Key: 'color.action.primary.fg@srgb',
//     apcaKey: 'color.action.primary.fg@srgb'
//   }
// ]
```

Skipped pairs use `status: 'skipped'` with `skippedReason: 'missing-background'`, `missing-foreground`, `missing-target`, or `alpha-unsupported`.
Alpha-involved contrast pairs are skipped because okcolor does not yet composite semi-transparent foreground/background chains for WCAG/APCA evaluation.

### Audit failure kinds

`result.report.summary.failures` contains deterministic failure records:

```ts
type AuditFailureKind = 'invalid-css' | 'out-of-gamut' | 'wcag2-regression'
```

- `invalid-css`: a target emitted invalid CSS.
- `out-of-gamut`: a target is outside the requested gamut or is not display-safe.
- `wcag2-regression`: a declared contrast pair failed the configured WCAG 2 gate.

`assertNoBlockingFailures(result)` blocks on all three by default. Pass `audit.failOn` to narrow the CI gate. Pass `audit.wcag2.level` or `audit.wcag2.requiredRatio` to change the WCAG threshold before the report is built.

### Usage

```ts
import { okColor } from 'okcolor'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [
    okColor(), // zero-config
  ],
})
```

The plugin processes `.css`, `.scss`, `.sass`, `.less`, `.styl`, `.stylus`, `.vue`, `.svelte`, and `.astro` files automatically.

Vite SFC virtual style modules are treated as CSS before URL query stripping, so ids such as `App.vue?vue&type=style&index=0&lang.css` are transformed correctly. Non-style virtual modules are skipped.

Embedded style transform failures are logged as `[okcolor]` warnings and return the original source.

## CLI

```bash
# Audit a directory
npx okcolor audit ./src

# Convert a single color
npx okcolor convert "#ff5a00" --to oklch

# Compile token JSON into CSS and a report
npx okcolor expand ./tokens.json --gamut p3 --out ./colors.css --report ./okcolor.report.json

# CI gate
npx okcolor check ./src --max-legacy-colors=10

# Diagnose issues
npx okcolor doctor ./src
```

See the [CLI documentation](/okcolor/getting-started/cli/) for all commands and options.
