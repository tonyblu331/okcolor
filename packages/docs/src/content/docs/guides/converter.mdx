## Convert against the actual engine

This playground is not a mock. It loads the generated Rust/WASM bundle and calls the same low-level conversion and gamut functions that power okcolor's compiler path.

## How to read the views

The **hue x chroma plane** fixes lightness and maps hue horizontally against chroma vertically. Painted samples are reachable in the selected target gamut. Empty samples are out of gamut. Drag inside the plane to pick a new OKLCH hue and chroma at the current lightness.

The **lightness x chroma slice** fixes hue and shows how much chroma that hue can hold across the lightness range.

The **sampled gamut boundary** projects RGB cube-face samples into OKLCH. This makes the important constraint visible: gamut is not one global saturation number. A hue can have plenty of room at one lightness and almost none at another.

## Expand vs saturate

**Expand** moves the source chroma toward the target gamut boundary while preserving OKLCH lightness and hue. Use it when you want a controlled wide-gamut enhancement that respects the available display range.

**Saturate** multiplies chroma first, then fits the result back into the target gamut. Use it when you want to test a more aggressive art-direction move, knowing that clipping pressure will appear sooner.

Neutral colors are intentionally protected. If chroma is near zero, the demo skips expansion so grays do not pick up accidental hue.

## Contrast feedback

The contrast panel checks the transformed color against black and white text with the same OKLCH relative-luminance path used by the token report. It is intentionally simple: pick the safer foreground, show the WCAG 2 ratio, and keep APCA/compliance policy in the token compiler reports.
