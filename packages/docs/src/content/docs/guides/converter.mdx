## How to read the viewer

The converter opens in source-inspection mode. Enable gamut mapping only when you want to compare the source against **Expand** or **Saturate**.

The converter uses one shared gamut viewer so the same source/result state can be inspected without juggling separate panels. Triangle and 3D live behind **More views** so the default stays focused.

In **2D**, the viewer fixes lightness and maps hue horizontally against chroma vertically. Painted samples are reachable in the selected target gamut, dimmed samples are outside it, and the labeled contour shows the exact `sRGB` or Display P3 boundary. Drag inside the frame to pick a new OKLCH hue and chroma at the current lightness.

In **Triangle**, the viewer fixes hue, places black and white on the base, and moves chroma toward the apex. Drag inside the triangle to adjust lightness and chroma without changing hue.

In **3D**, the same viewer maps hue around the volume, chroma outward, and lightness vertically. Drag to rotate the space and compare the source point against the mapped result.

## Expand vs saturate

**Expand** moves the source chroma toward the target gamut boundary while preserving OKLCH lightness and hue. Use it when you want a controlled wide-gamut enhancement that respects the available display range.

**Saturate** multiplies chroma first, then fits the result back into the target gamut. Use it when you want to test a more aggressive art-direction move, knowing that clipping pressure will appear sooner.

Neutral colors are intentionally protected. If chroma is near zero, the demo skips expansion so grays do not pick up accidental hue.

## Contrast feedback

The contrast panel checks the transformed color against black and white text with the same OKLCH relative-luminance path used by the token report. It is intentionally simple: pick the safer foreground, show the WCAG 2 ratio, and keep APCA/compliance policy in the token compiler reports.
