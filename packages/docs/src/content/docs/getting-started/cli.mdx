## Usage

```bash
npx @tonybonet/okcolor audit ./src
npx @tonybonet/okcolor convert "#ff5a00" --to oklch
npx @tonybonet/okcolor expand ./tokens.json --gamut p3 --out ./colors.css --report ./okcolor.report.json
```

The CLI is the automation surface for okcolor: audit frontend color debt, convert individual colors, and compile design-token JSON into fallback-first CSS. For automatic CSS file transformation in apps, use the Vite plugin.

## Commands

### `okcolor convert <color|tokens.json>`

Convert a single color faithfully, or compile token JSON as sRGB fallback CSS:

```bash
okcolor convert "#ff5a00" --to oklch
okcolor convert ./tokens.json --out ./colors.css
```

Supported single-color output spaces are `hex`, `rgb`, `hsl`, `hwb`, and `oklch`.

### `okcolor expand <color|tokens.json>`

Preserve OKLCH lightness and hue, then use part of the Display P3 chroma headroom:

```bash
okcolor expand "#ff5a00" --gamut p3 --amount 0.75
okcolor expand ./tokens.json --gamut p3 --amount 0.75 --out ./colors.css --report ./okcolor.report.json
okcolor audit ./tokens.json --wcag2 aaa --fail-on wcag2-regression
```

Token output is fallback-first: base sRGB custom properties, diagnostic OKLCH variables, then `@media (color-gamut: p3)` overrides.

### `okcolor grade <color|tokens.json>`

Apply an art-directed recipe after conversion:

```bash
okcolor grade "#0055ff" --recipe premium --gamut p3
```

Available recipes are `literal`, `vivid`, `deeper`, `premium`, `muted`, `softer`, `warmer`, and `cooler`.

### `okcolor fit <color|tokens.json>`

Reduce chroma until a color fits a target gamut:

```bash
okcolor fit "oklch(70% 0.35 145)" --gamut srgb
```

### `okcolor describe <color>`

Explain the source OKLCH identity and target gamut headroom without mutating the color:

```bash
okcolor describe "#ff5a00" --gamut p3
```

### `okcolor audit <path|tokens.json>`

Scan CSS files and report legacy color usage. For token JSON, emit the token compiler report, including declared foreground/background contrast pairs. Recursively walks directories:

```bash
npx @tonybonet/okcolor audit ./src
```

<TerminalDemo scenario="audit" />

Output options:

```bash
# JSON output for automation
npx @tonybonet/okcolor audit ./src --format=json
```

Directory traversal follows symlinked CSS files and directories, tracks real directory paths to avoid cycles, and warns instead of crashing on dangling symlinks.

Token contrast is role-pair based. A background token can declare its foreground token:

```json
{
  "color.action.primary.bg": {
    "$type": "color",
    "$value": "#0055ff",
    "okcolor": {
      "text": "color.action.primary.fg",
      "contrast": "wcag2-aa"
    }
  },
  "color.action.primary.fg": "#ffffff"
}
```

Reports audit both fallback and P3 targets independently, with keys such as `color.action.primary.fg@srgb` and `color.action.primary.fg@p3`. WCAG 2 AA is the default CI-blocking gate; use the policy flags for AAA or a custom ratio. APCA is advisory and reported as an `lc` value, polarity, and `pass-body`/`pass-large`/`fail` hint.

Token compiler reports include top-level `schemaVersion: 1`. Pin this in CI before reading nested fields so report-contract changes fail loudly instead of corrupting downstream dashboards.

WCAG policy is build-time only. Use `--wcag2 aa`, `--wcag2 aaa`, or `--min-contrast <ratio>` to change the contrast gate without importing runtime JavaScript into your app.

## Failure modes

okcolor keeps machine data and human diagnostics separate: JSON/CSS output is written to stdout or `--out`, while errors and usage help are written to stderr. Failed commands exit with code `1`.

| Case | Where it appears | Behavior |
| ---- | ---------------- | -------- |
| Unknown recipe | CLI stderr, token compiler error | `grade --recipe unknown` and invalid token `okcolor.recipe` values fail with the supported recipe list. Token aliases must be defined in `options.recipes` or use a built-in recipe. |
| Unsupported color space | `report.diagnostics[]` | Design Token component objects only accept `$value.colorSpace: "srgb"`. Other spaces are skipped with an `unsupported-color-space` warning diagnostic. |
| Malformed token | `report.diagnostics[]` | Unsupported token shapes or invalid sRGB component arrays are skipped with `unsupported-token-shape` or `invalid-color-components` warning diagnostics. Valid tokens still compile. |
| Contrast regression | `report.summary.failures[]`, CLI stderr when blocking | Declared foreground/background pairs fail the configured WCAG 2 gate. APCA remains advisory only. |
| Missing or unsupported contrast pair endpoint | `report.contrastPairs[]` | If a declared foreground/background token is missing, malformed, lacks a compiled target, or uses alpha, the pair is reported as `skipped` with `missing-background`, `missing-foreground`, `missing-target`, or `alpha-unsupported`. |
| Out-of-gamut output | `report.summary.failures[]`, CLI stderr when blocking | A target whose generated CSS is invalid, not display-safe, or outside the requested gamut is reported under `invalid-css` or `out-of-gamut`. |

### `okcolor check <path>`

CI gate. Fails with exit code 1 if legacy colors exceed a limit. Use this to enforce color modernization in your pipeline:

```bash
npx @tonybonet/okcolor check ./src --max-legacy-colors=10
```

```bash
# Allow named colors (gray, white, black are often fine as-is)
npx @tonybonet/okcolor check ./src --max-legacy-colors=10 --allow-named
```

### `okcolor scope <path>`

Diagnose color issues in your stylesheets: malformed values, extreme lightness, or unusual patterns:

```bash
npx @tonybonet/okcolor scope ./src
```

## Programmatic API

The same engine is available programmatically via `@tonybonet/okcolor/core`:

```ts
import { transformCss, auditCss } from '@tonybonet/okcolor/core'

const result = transformCss(`
  .btn { color: #ff0000; }
`)
console.log(result)
// .btn { color: oklch(62.8% 0.25768 29.23); }

const stats = auditCss(`
  .btn { color: #3b82f6; }
  .alert { border-color: red; }
`)
console.log(stats.legacy_count) // 2
console.log(stats.hex_count) // 1
console.log(stats.named_count) // 1
```

See the [API Reference](/okcolor/reference/api/) for the full interface.
