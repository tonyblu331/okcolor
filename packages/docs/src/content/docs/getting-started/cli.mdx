## Usage

```bash
npx okcolor input.css -o output.css
```

The CLI is a thin wrapper around the same Rust/WASM engine used by the Vite plugin. Every color that passes through gets the exact same W3C-compliant conversion.

<TerminalDemo scenario="transform" />

## Commands

### `okcolor <input> [output]`

Transform a CSS file. This is the default command — you can omit the `transform` keyword:

```bash
okcolor input.css -o output.css
```

If `-o` is omitted, output goes to stdout.

### `okcolor audit <path>`

Scan CSS files and report legacy color usage. Recursively walks directories:

```bash
npx okcolor audit ./src
```

<TerminalDemo scenario="audit" />

Output options:

```bash
# JSON output for automation
npx okcolor audit ./src --format=json
```

### `okcolor check <path>`

CI gate. Fails with exit code 1 if legacy colors exceed a limit. Use this to enforce color modernization in your pipeline:

```bash
npx okcolor check ./src --max-legacy-colors=10
```

```bash
# Allow named colors (gray, white, black are often fine as-is)
npx okcolor check ./src --max-legacy-colors=10 --allow-named
```

### `okcolor doctor <path>`

Diagnose color issues in your stylesheets: malformed values, extreme lightness, or unusual patterns:

```bash
npx okcolor doctor ./src
```

## Programmatic API

The same engine is available programmatically via `okcolor/core`:

```ts
import { transformCss, auditCss } from 'okcolor/core'

const result = transformCss(`
  .btn { color: #ff0000; }
`)
console.log(result)
// .btn { color: oklch(62.8% 0.25768 29.23); }

const stats = auditCss(`
  .btn { color: #3b82f6; }
  .alert { border-color: red; }
`)
console.log(stats.legacy_count) // 2
console.log(stats.hex_count)    // 1
console.log(stats.named_count)  // 1
```

See the [API Reference](/okcolor/reference/api/) for the full interface.
