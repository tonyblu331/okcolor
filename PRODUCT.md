# Product

## Register

brand

## Users

Frontend engineers, design-system maintainers, and technical designers who already work with CSS tokens, Vite, and modern color spaces. They are usually migrating existing sRGB colors, validating generated CSS, or learning why OKLCH gives better control than Hex/HSL.

## Product Purpose

okcolor modernizes legacy web color at build time. It preserves author intent, converts old color formats into OKLCH, optionally expands chroma into wider gamuts, and audits contrast before generated CSS ships.

## Brand Personality

Precise, opinionated, tactile.

## Anti-references

- Generic blue or purple SaaS docs.
- Decorative gradients used as brand texture.
- Yellow accessibility-checker clone; the reference is interaction density, not palette.
- Dull default documentation pages where the converter feels trapped inside a prose wrapper.
- Tiny dashboard cards and generic glassmorphism.
- Green/cream documentation palettes and card-heavy dashboards.

## Design Principles

1. Show color as measured material, not decoration.
2. Let the converter act as the product proof, not a side demo.
3. Teach hue, chroma, and lightness through interaction before prose.
4. Keep spectral color inside scientific visualizations; surrounding UI stays flat and deliberate.
5. Preserve engineering trust: visible fallbacks, labels, contrast, and build-time constraints.

## Accessibility & Inclusion

Target WCAG 2 AA for documentation and controls. Do not rely on hue alone for status. Respect reduced motion. Keep numeric color values copyable and readable. Gamut visualizations must include labels, boundaries, and source/result markers so color-blind users can still understand state changes.
